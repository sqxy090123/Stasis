# 进程管理模块

**文件**: `process_manager.c` (122 行)

职责：进程挂起/恢复核心 API、进程枚举/内存查询、关键进程/白名单/前台/自我保护判断、SeDebugPrivilege 提权。

## 核心 API

| 函数 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `InitProcessAPI` | `void` | `BOOL` | `LoadLibrary ntdll.dll` → `GetProcAddress NtSuspendProcess/NtResumeProcess` 存入全局函数指针 |
| `EnableDebugPrivilege` | `void` | `BOOL` | `OpenProcessToken` → `LookupPrivilegeValue SE_DEBUG_NAME` → `AdjustTokenPrivileges` 启用 |
| `SuspendProcessByPid` | `DWORD pid` | `BOOL` | `OpenProcess(PROCESS_SUSPEND_RESUME)` → `NtSuspendProcess` → `LogEvent("Frozen PID %lu")` |
| `ResumeProcessByPid` | `DWORD pid` | `BOOL` | `OpenProcess(PROCESS_SUSPEND_RESUME)` → `NtResumeProcess` → `LogEvent("Resumed PID %lu")` |
| `EnumProcessesEx` | `DWORD* pids, int maxCount, int* outCount` | `BOOL` | `EnumProcesses` 缓冲区不足时返回 `maxCount` (兼容大量进程) |
| `GetProcessMemoryKB` | `DWORD pid, SIZE_T* memKB` | `BOOL` | `OpenProcess(QUERY_LIMITED_INFORMATION|VM_READ)` → `GetProcessMemoryInfo` → `WorkingSetSize/1024` |
| `IsCriticalProcess` | `const WCHAR* name` | `BOOL` | 遍历 `SystemWhitelist[10]` `_wcsicmp` 匹配 |
| `IsProcessInUserWhitelist` | `const WCHAR* name` | `BOOL` | 临界区保护遍历 `g_State.userWhitelist` `_wcsicmp` |
| `IsProcessForeground` | `DWORD pid` | `BOOL` | `GetForegroundWindow` → `GetWindowThreadProcessId` 比对 |
| `IsCurrentProcess` | `DWORD pid` | `BOOL` | `pid == GetCurrentProcessId()` 自我保护 |

## 关键流程

### 1. 初始化 (启动期 `main.c:46-49`)

```c
EnableDebugPrivilege();  // 必须先提权，否则 OpenProcess 无权挂起系统进程
if (!InitProcessAPI()) {  // 加载 ntdll 获取 NtSuspend/ResumeProcess
    MessageBoxW(NULL, L"无法加载进程挂起/恢复API，程序无法运行。", L"错误", MB_ICONERROR);
    return 1;
}
```

### 2. 挂起流程 (`monitor_engine.c:92`)

```c
if (!SuspendProcessByPid(procs[i].pid)) continue;  // 失败跳过
EnterCriticalSection(&g_State.cs);
if (g_State.frozenCount < 1024)
    g_State.frozenStack[g_State.frozenCount++] = procs[i].pid;
LeaveCriticalSection(&g_State.cs);
frozenThisRound++;
Sleep(100);  // 限速
```

### 3. 恢复流程 (`monitor_engine.c:115`)

```c
DWORD pid = g_State.frozenStack[--g_State.frozenCount];
LeaveCriticalSection(&g_State.cs);
ResumeProcessByPid(pid);  // 锁外调用
EnterCriticalSection(&g_State.cs);
```

### 4. 白名单/保护检查 (`monitor_engine.c:73-75`)

```c
if (IsCriticalProcess(name)) continue;           // 系统白名单
if (IsProcessForeground(pid)) continue;          // 前台进程
if (IsProcessInUserWhitelist(name)) continue;    // 用户白名单
if (IsCurrentProcess(pid)) continue;             // 自我保护
```

## 线程安全

| 操作 | 同步方式 |
|------|----------|
| `userWhitelist` 读/写 | `EnterCriticalSection(&g_State.cs)` / `LeaveCriticalSection` |
| `frozenStack` 入栈/出栈 | 同上 |
| `IsProcessInUserWhitelist` | 函数内加锁 (极短临界区，仅 `_wcsicmp` 循环) |
| `NtSuspendProcess`/`NtResumeProcess` | **锁外** 调用 (避免阻塞 UI/监控线程) |

## 错误处理策略

| 场景 | 行为 |
|------|------|
| `OpenProcess` 失败 (权限不足/进程已退出) | 返回 `FALSE`，上层 `continue` 跳过该 PID |
| `NtSuspendProcess` 失败 | 返回 `FALSE`，不入栈，`LogEvent` 不记录 (避免刷屏) |
| `EnumProcesses` 缓冲区不足 | 返回 `maxCount`，上层按返回数量处理 (可能漏掉尾部进程) |
| `GetProcessMemoryInfo` 失败 | 返回 `FALSE`，上层显存显示 0 KB |
| `EnableDebugPrivilege` 失败 | `InitProcessAPI` 仍返回 `TRUE` (仅权限不足时后续挂起会失败) |

## 设计权衡

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| `NtSuspendProcess` (当前) | 内核级、无需注入线程、支持任意进程、极简 | 非文档 API、极少数杀毒软件误报 | 最小依赖、单文件分发友好 |
| `CreateRemoteThread` + `SuspendThread` | 文档化、可控 | 需注入、线程级挂起可能不一致、复杂 | 过度工程 |
| `Job Object` + `JOB_OBJECT_LIMIT_SILENT_BREAKAWAY_OK` | 组管理 | 仅限子进程、需创建 Job | 不适用现有进程 |

## 扩展点

| 需求 | 实现建议 |
|------|----------|
| 精细化 `svchost.exe` 白名单 (按服务名) | `OpenSCManager` + `EnumServicesStatusEx` 解析 `svchost.exe -k` 参数匹配 |
| 进程树冻结 (父进程冻结连带子进程) | `CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS)` 遍历 `th32ParentProcessID` 递归 |
| 挂起超时保护 | `SuspendProcessByPid` 改为异步：工作线程 `NtSuspendProcess` + `WaitForSingleObject(hThread, SUSPEND_TIMEOUT_MS)` 超时 `TerminateThread` 回滚 |
| 记录挂起失败原因 | `LogEvent(L"Suspend failed PID %lu err=%lu", pid, GetLastError())` |
