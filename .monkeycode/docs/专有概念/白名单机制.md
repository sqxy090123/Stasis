# 白名单机制

**白名单机制** 通过 **双层过滤** (系统静态 + 用户动态) 保护关键进程不被误冻结，确保系统稳定性与用户自定义需求并存。

## 什么是白名单机制？

| 层级 | 来源 | 存储 | 进程名示例 | 修改方式 |
|------|------|------|------------|----------|
| **系统白名单** | 代码硬编码 | `process_manager.c` 静态数组 | `System` `Idle` `csrss.exe` `winlogon.exe` `services.exe` `lsass.exe` `svchost.exe` `explorer.exe` `dwm.exe` `taskmgr.exe` | 重新编译 |
| **用户白名单** | `Stasis.ini` | 动态堆数组 `WCHAR** userWhitelist` | 用户添加的任意进程名 (如 `chrome.exe` `code.exe`) | UI "白名单" 按钮 (待实现) / 手动编辑 INI |

冻结决策流程 (`monitor_engine.c:73-75`)：

```c
if (IsCriticalProcess(name) || IsProcessForeground(pid)) continue;  // 系统关键/前台
if (IsProcessInUserWhitelist(name)) continue;                         // 用户白名单
if (IsCurrentProcess(pid)) continue;                                  // 自我保护
// → 进入候选冻结池
```

## 关键特征

| 特征 | 说明 |
|------|------|
| **系统级不可改** | 覆盖 Windows 核心进程，防止蓝屏/会话断开/任务管理器失效 |
| **用户级可扩展** | INI 持久化，分号分隔，运行时动态增删，受临界区保护 |
| **大小写不敏感** | `_wcsicmp` 比较，`notepad.exe` == `NOTEPAD.EXE` |
| **仅匹配文件名** | `QueryFullProcessImageNameW` 取完整路径 → `wcsrchr(path, L'\\')` 取文件名 → 比较 |
| **线程安全** | `EnterCriticalSection(&g_State.cs)` 保护 `userWhitelist` 读写 |
| **自我保护独立** | `IsCurrentProcess(pid)` 单独判断，不依赖白名单 |

## 系统白名单完整列表

| 进程名 | 角色 | 冻结后果 |
|--------|------|----------|
| `System` (PID 4) | 内核系统进程 | 系统全面冻结、蓝屏 |
| `Idle` (PID 0) | 空闲进程 | 无实际影响但无意义 |
| `csrss.exe` | 客户端/服务器运行时子系统 | GUI 子系统崩溃、黑屏 |
| `winlogon.exe` | 登录/安全子系统 | 无法登录/解锁、需强制重启 |
| `services.exe` | 服务控制管理器 | 所有服务停止、系统瘫痪 |
| `lsass.exe` | 本地安全认证 | 认证失效、无法获取权限 |
| `svchost.exe` | 服务宿主 (多实例) | 关键服务 (网络、更新、音频等) 停止 |
| `explorer.exe` | Shell (桌面/任务栏/文件管理) | 任务栏/开始菜单/桌面消失 |
| `dwm.exe` | 桌面窗口管理器 | 合成/动画/缩略图失效、黑屏闪烁 |
| `taskmgr.exe` | 任务管理器 | 用户无法手动干预/结束卡死进程 |

> **注意**：`svchost.exe` 多实例共名，白名单会保护**所有** `svchost.exe`。如需精细控制需改为 PID/服务名匹配 (当前未实现)。

## 用户白名单 INI 格式

`Stasis.ini` 示例：

```ini
[Settings]
CpuThreshold=85
MemThreshold=90
ThawThreshold=60
AutoMode=1
Whitelist=chrome.exe;code.exe;notepad++.exe;WeChat.exe
```

读取解析 (`settings_store.c:15-48`)：

```c
GetPrivateProfileStringW(L"Settings", L"Whitelist", L"", buf, 2048, CONFIG_FILE);
WCHAR* context = NULL;
WCHAR* token = wcstok_s(buf, L";", &context);
while (token) {
    while (*token == L' ') token++;  // 去前导空格
    if (*token) {
        EnterCriticalSection(&g_State.cs);
        // realloc 扩容 + malloc 复制字符串
        g_State.userWhitelist[g_State.whitelistCount] = malloc((wcslen(token)+1)*sizeof(WCHAR));
        wcscpy_s(g_State.userWhitelist[g_State.whitelistCount], wcslen(token)+1, token);
        g_State.whitelistCount++;
        LeaveCriticalSection(&g_State.cs);
    }
    token = wcstok_s(NULL, L";", &context);
}
```

写入拼接 (`settings_store.c:63-73`)：

```c
WCHAR whitelistStr[2048] = {0};
EnterCriticalSection(&g_State.cs);
for (int i=0; i<g_State.whitelistCount; i++) {
    wcscat_s(whitelistStr, 2048, g_State.userWhitelist[i]);
    if (i < g_State.whitelistCount-1) wcscat_s(whitelistStr, 2048, L";");
}
LeaveCriticalSection(&g_State.cs);
WritePrivateProfileStringW(L"Settings", L"Whitelist", whitelistStr, CONFIG_FILE);
```

## 线程安全模型

| 操作 | 线程 | 加锁范围 |
|------|------|----------|
| 遍历判断 `IsProcessInUserWhitelist` | 监控线程 (高频) | `EnterCS` → 循环 `_wcsicmp` → `LeaveCS` (仅读，锁粒度极小) |
| 读取 INI 填充数组 | 主线程 (启动一次) | 单线程，无竞争 |
| 写入 INI 拼接字符串 | 主线程 (用户改设置) | `EnterCS` → 循环 `wcscat_s` → `LeaveCS` |
| UI 新增/删除 | 主线程 (待实现) | 同上 |

> **性能注**：监控线程每 500ms 调用一次 `IsProcessInUserWhitelist`，白名单通常 < 20 项，`_wcsicmp` 极快，锁竞争可忽略。

## 设计权衡

| 方案 | 优点 | 缺点 | 选择理由 |
|------|------|------|----------|
| **双层数组 + INI** (当前) | 简单、无依赖、启动快、内存小 | 用户增删需 UI/手动编辑 INI | 符合单 EXE 无依赖目标 |
| 注册表存储 | 系统标准位标准位置、ACL 可控 | 需管理员写 HKLM、读写较慢 | INI 同目录更便携 |
| SQLite/JSON | 结构化、可扩展 | 引入解析库、体积增大 | 过度设计 |
| 进程对象安全描述符检查 | 精细到 PID/会话/签名 | 复杂、需 `SeSecurityPrivilege` | 维护成本高 |

## 扩展建议

1. **UI 实现**：`app_window.c` 中 `IDC_BTN_WHITELIST` 点击弹出模态对话框 (`DialogBoxParam`)，`ListView` 显示现有白名单，提供 "添加/删除/从运行进程选择" 按钮，确定时调用 `SaveSettings`
2. **通配符支持**：`chrome*.exe` / `*host.exe` → 解析时 `PathMatchSpecW`
3. **导入/导出**：按钮导出 `whitelist.txt` / 导入合并去重
4. **进程树保护**：父进程在白名单 → 子进程自动豁免 (需 `CreateToolhelp32Snapshot` 遍历父子关系)
5. **签名验证**：`WinVerifyTrust` 验证 Microsoft/知名厂商签名 → 自动加入临时白名单
